# DIRAC – code map

DIRAC is a relativistic quantum chemistry program (https://www.diracprogram.org),
written mostly in Fortran (F77 fixed-form `.F` and F90 `.F90`) with some C/C++,
built with CMake and driven by the Python run script `pam`.

## Top-level layout

| Path | Contents |
|---|---|
| `src/` | Program source, one directory per module (see below) |
| `test/` | End-to-end test suite, one directory per test |
| `cmake/` | Build system: `autocmake.yml`, `custom/*.cmake` (DIRAC's own), `downloaded/` (Autocmake modules, do not edit) |
| `setup` | Configure front end (generated by Autocmake from `cmake/autocmake.yml`) |
| `external/` | Bundled third-party projects built as CMake ExternalProjects (git submodules `unit-tests`, `stieltjes`) |
| `utils/` | Auxiliary programs and scripts (`pam` sources, `labread`, `cfread`, `diag`, basis tools, ...) |
| `basis/`, `basis_dalton/`, `basis_ecp/` | Basis set and ECP libraries |
| `doc/` | Sphinx documentation (`manual/`, `installation/`, `development/`, `tutorials/`) |
| `configuration-examples/` | Build recipes for specific machines/compilers |
| `maintenance/` | Developer maintenance scripts |

Untracked `*.bak` files may be present all over `src/`; they are not part of the code.

## Program flow

`src/main/main.F90` → `src/main/dirac.F`: `DIRCTL` reads input (`PAMINP`, in
`src/dirac/dirrdn.F`), sets up (`PAMSET`, `src/dirac/dirset.F`), then `PAMDRV` →
`PAMPSI` runs, in order: SCF, MCSCF, 4-index transformation, correlation
methods, then properties (`PAMPRP`). Input keyword parsing is spread over the
`*inp`/`*rdn` routines of each module; see `doc/development/input_reading.rst`.

## Source directories (`src/`)

**Integrals and Hamiltonians**
- `abacus/` – HERMIT integral code from Dalton: `her1*` one-electron, `her2*`
  two-electron integrals and direct Fock builds, `herrdn_dirac.F` input;
  `aba*` geometric derivatives / properties.
- `interest/` – InteRest two-electron integral library (`module_interest_*`).
- `gen1int/` – Gen1Int one-electron integral library (git subtree in `subtree/`).
- `ecp/` – Effective core potential integrals.
- `x2c/` – Exact two-component (X2C) Hamiltonian; `amfi/`, `x-amfi/` – atomic
  mean-field spin-orbit integrals.
- `dirac/dirone.F`, `dirac/dirtwo.F` – one-/two-electron Fock matrix contributions.

**SCF (Hartree–Fock / Kohn–Sham)**
- `dirac/` – core of DIRAC: `dirscf.F` (`PSISCF`, DIIS/SCF iterations),
  `dirrdn.F` (main input reading), `dirset.F`, `dirden.F` (densities),
  `dirana.F` (analysis), `dirgeo.F` (geometry optimization driver), `huckel.F`.
- DFT: `xcint/` (exchange–correlation integration), `grid/` (numerical grids),
  `xcfun/` and `cfun/` (functional libraries), `srdft/` (range-separated DFT).
- Environment: `pcm/` (PCM solvation), `pelib/` (polarizable embedding,
  subtree), `fde/` (frozen-density embedding).

**Correlation**
- `moltra/` – 4-index AO→MO transformation (`PAMTRA`, `trapam.F`), MP2 (`PSIMP2`).
- `relccsd/` – RELCCSD: CCSD(T), Fock-space CC, EOM-CC (`ccpam.F`: `PAMCCM`).
- `exacorr/` – ExaCorr tensor-based CC (`exacorr_dirac.F`: `EXA_CC`), uses ExaTensor/TBLIS.
- `krcc/` – Kramers-restricted (GAS) coupled cluster.
- `krmc/` – KR-MCSCF and KR-CI (`krmcopt.F`: `PSIOPT`).
- `dirrci/` – Direct RCI (`cidirr.F`: `PAMCIM`).
- `lucita/`, `luciarel/` – LUCITA (spin-free) and LUCIAREL (relativistic) GAS-CI.
- `reladc/` – Relativistic ADC (`adccore.F`: `PAMADC`) and Polarization
  propagator (`polprp_driver.F`: `PAMPOLPRP`).
- `caspt2/` – CASPT2; `laplace/`, `laplace-minimax/` – Laplace transformation
  of orbital-energy denominators (minimax); `qcorr/` – Davidson-type
  size-consistency corrections for CI energies.

**Properties and response**
- `prp/` – property module (`pamprp.F`): linear/quadratic response, excitation
  energies, NMR/EPR (`esr/`), London orbitals.
- `openrsp/` – OpenRSP response interface; `visual/` – densities/currents on grids.

**Infrastructure**
- `gp/` – general-purpose utilities: memory allocator, file handling, checkpoint
  (HDF5), quaternion algebra, `dirac_cfg.F90`.
- `include/` – common-block `.h` include files shared across modules.
- `input/` – new-style input reader; `main/` – program entry and MPI framework;
  `interface_mpi/` – MPI wrappers; `pdpack/` – linear algebra helpers and the
  builtin BLAS/LAPACK fallback; `matrix_operations/`, `localization/`, `rose/`
  (ROSE localized orbitals, subtree), `mfsolver/` (iterative eigenvalue-solver settings).

## Build

```bash
./setup [--mpi] [--int64] [--fc=... --cc=... --cxx=...] build   # configure into build/
cd build && make -j N                                             # builds dirac.x, pam, utilities
```

`./setup --help` lists options; `./setup --show` prints the CMake command
without running it. Math libraries (BLAS/LAPACK) are detected by
`cmake/downloaded/autocmake_math_libs.cmake`.
Adding/removing source files: edit the module's `CMakeLists.txt`
(see `doc/development/adding_moving_removing_sources.rst`).

## Tests

- Each test is a directory `test/<name>/` with input (`*.inp`), molecule
  (`*.mol`/`*.xyz`), a Python script `test` (using the `runtest` library in
  `test/runtest/`, configured in `test/runtest_config.py`) and reference
  outputs in `result/`.
- Tests are registered in `cmake/custom/test.cmake` with
  `dirac_test(<name> "<labels>" "<timeout>")`. Labels include runtime
  (`short`, `medium`, `long`, `verylong`) and topic (`scf`, `dft`, `cc`, ...).
  A new test must be added there or it never runs.

Run tests from the build directory:

```bash
cd build
ctest -R '^dft_alda$'      # a single test (-R is a regex)
ctest -R dft_alda -V       # verbose output
ctest -L short -j 4        # all tests with label "short"
```

Or run a single test script directly. Inputs are copied to and outputs written
in the work dir (default: the test's source directory). Use absolute paths, as
`--binary-dir` is resolved relative to the work dir:

```bash
python3 test/x2c-SCF_to_4c-SCF/test --binary-dir=$PWD/build --work-dir=/tmp/x2c_test --verbose
# add --launch-agent="mpirun -np 4" for MPI builds; ./test --help for more options
```

Running DIRAC by hand: `build/pam --inp=file.inp --mol=file.mol`
(`build/pam --help` for options).

Unit tests (`-DENABLE_UNIT_TESTS=ON`) come from the `external/unit-tests`
submodule; see `cmake/custom/unit/unit_tests.cmake`.

More developer documentation: `doc/development/` (testing, debugging, commit policy).
