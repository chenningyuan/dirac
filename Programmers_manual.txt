Programmers manual for DIRAC-2002

Lucas Visscher, 23-8-2002

The DIRAC programme system is maintained using the CVS and contains a number of shell 
scripts in order to extract a distribution version and to insert machine dependent lines.
Programmers should have some knowledge of these procedures, especially when adding or
deleting source files or directories. Below I will briefly describe the most important
features of the set up and indicate how essential files should be modified
when extending the programme with new modules.

1. Source and derived files.
Not all of the files that you see in the directory are residing in CVS. Take for instance
a freshly checked-out version of DIRAC and look for the Makefile. You will not find it !
The reason is that this file and others are generated by the pamadm script.

2. Optional modules.
The main reason to have a pamadm script is to be able to write different Makefiles
depending on how many "experimental" modules are included. These additional modules 
(like for instance dft) are in a separate directory and will not be
added when the program is distributed outside the authors group.

3. The pamadm script.
This script should always be run when new files or directories are added to the repository.
It creates all the Makefiles and the configure and exports scripts (see below). 
The author of the new files should take care that this script is modified so that these
derived files contain proper reference to the new code. It should be rather straightforward
to do this by looking at the example provide by other (optional) modules.
DO NEVER EDIT THE MAKEFILE OR CONFIGURE SCRIPTS. They are derived files and are overwritten
by pamadm. The files to be changed are pamadm and configure.in.

4. The configure script.
This script take care of the machine dependent code. Please use this only for this 
purpose and DO NOT ADD MODULE RELATED INFORMATION. This was done in previous releases
of DIRAC and made things more complicated. The configure script contains references to the
GNU files configure.sub and config.guess that should not be edited. New versions should
rather be obtained from the Free Software Foundation. Please do only change configure.in,
e.g. when adding support for new operating systems (you should basically only put
in info about the best compiler and compiler options for DIRAC, which should be quite
straightforward).

5. The export script.
This script creates an export version (tar-tape) that can be used to distribute DIRAC
without or with only one of the optional modules active. 

6. The testlast script.
Use this script BEFORE checking in new code to verify that your modifications do not
affect other functionality. More documentation on this script is to be written.

NOTE : This documentation is the bare minimum. I plan to add more but may not have the time.
If you have and know what to write, please extend this... (LV,23-8-2002).
