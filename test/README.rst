Description of the test procedure
=================================


General setup
-------------

In each subdirectory you will find the routine menu that functions as a
template for the execution of a particular test. Have a look at present menu
files to get inspirations and to see working examples.

The whole test suite or part of the test suite is run with the 'runtest' command
in the ../ directory. For information about options type:
$ ../runtest --help


The filtering
-------------

Once the execution of DIRAC is filtered you can compare the new output with
the reference output that is present in the result directory. If one would
use simply the unix command diff here one would always see differences, simply
because dates and execution times will be different, because insignificant
last digits are different, or because output formatting has changed. To
focus on relevant differences we use the script crep to find the relevant
numbers that are to be checked. The idea is that you define a characteristic
text that is contained in the output just BEFORE the numbers that are to
be checked. Here you may either use a string or a regular expressions, examples
of both can be found when looking at the filter files. This defines the start
of the output section to be tested, but you also want to define the end. Here
there are two possibilities, you either know in advance how many lines you
want to test, or you don't (keep in mind that others may later introduce
additional blank or text lines). In the first case you can simply specify the
number of lines to be test (using NLines), in the second case you have to
specify a characteristic text that closes the section.
I hope this is clear, please look at the examples already present and see how
they take out text. Then use the one best suited for your needs and test the
working by running just crep and looking at the resulting .rep file. Iterate
until the only numbers contained in that section are the ones you want to test.


The actual testing
------------------

This is handled by the bdrep (text output) and drep (html output) that write
the relative differences larger than the given threshold (specified by $ERROR).
In addition a single line is written to the log if a difference is found
NB: These scripts compare ALL numbers in the extract generated by crep as they
have no way of knowing which are meaningful and which are not. YOU need to
do this by making the correct filter!


How to add a new test
---------------------

1. Copy an existing test and choose a sensible name, e.g. not
   my_favorite_test or test2, but for instance symmetry_recognition to signal that
   we are testing the symmetry recognition procedure.

2. Put the inp and mol file(s) in the directory and modify the
   menu file to work with these filenames.

3. Put a correct output in the result directory and modify the filter file to
   take out the part that is relevant for the functionality that you want to test.
   Don't test everything, e.g. the electronic Hartree-Fock energy is already
   tested at several places, no need to do this in every test.  Run just crep and
   see whether you are satisfied with the result.

4. Go to the top directory and run the script runtest with your new test.  Test
   that it runs OK. Verify that it actually produced non-empty rep files in your
   new directory/compare.  It is a good practice to test your test, try to
   introduce deliberately errors in your new code and check whether your new test
   catches the error - if not, modify the test.

5. If the test works look at how long it takes to run on a single PC to see where
   it should be quick or regular. A rule of thumb: < 10 seconds = quick, otherwise regular.

6. Add the test to pamadm (search for existing tests to see how).

7. Use git add and git commit to commit your work to the repository.  Make sure
   to include ALL files, don't forget the result directory that should contain the
   reference output and filter files. You can verify this with "git status".
